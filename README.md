# 銀河将棋X² / Galaxy Shogi X²

Three.js + TypeScript + Vite で動く、ブラウザ用「3Dローグライク将棋」です。
通常の将棋の戦略性に、ターンごとのランダム強化・特殊コマ・盤面ギミック・本拠地HP
といったローグライク要素を組み合わせています。

タイトル画面から**軍師（キャラクター）を選んで出陣**。各軍師は **パッシブスキル** と
**奥義（アクティブ必殺技／クールダウン制）** を持ちます。
プレイヤー vs 簡易AI。各ターン開始時にカード形式で3つの能力から1つを選んで強化します。

---

## 起動方法

```bash
npm install      # 依存関係のインストール
npm run dev      # 開発サーバー起動（http://localhost:5173 が自動で開きます）
```

その他のスクリプト:

```bash
npm run build      # 型チェック + 本番ビルド（dist/ に出力）
npm run preview    # ビルド結果のプレビュー
npm run typecheck  # 型チェックのみ
```

動作確認: Node.js 18+ 推奨（Node 26 / npm 11 で動作確認済み）。WebGL 対応ブラウザが必要です。

## GitHub Pages へ公開する

自動デプロイ用の GitHub Actions ワークフロー（`.github/workflows/deploy.yml`）を同梱しています。
リポジトリを作って push するだけで、`main` への push ごとに自動でビルド＆公開されます。

```bash
# 1. GitHub で空のリポジトリを作成（README等は入れない）。例: rogue-shogi-3d
# 2. このフォルダで remote を追加して push
git remote add origin https://github.com/<あなたのユーザー名>/<リポジトリ名>.git
git push -u origin main
```

3. GitHub のリポジトリ **Settings → Pages → Build and deployment → Source** を
   **「GitHub Actions」** に設定。
4. **Actions** タブでデプロイ完了を待つと、
   `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

> Vite の `base` は本番ビルド時のみ相対パス（`./`）になるため、
> リポジトリ名がどんな名前でもそのまま動きます（設定変更不要）。
> `gh` CLI を使う場合は `gh repo create <名前> --public --source=. --push` の後に
> Pages の Source を GitHub Actions にするだけです。

## 操作方法

| 操作 | 内容 |
|------|------|
| **左ドラッグ** | 視点（カメラ）の回転 |
| **マウスホイール** | ズームイン / アウト |
| **コマをクリック** | 自分のコマを選択（移動可能マスが光ります） |
| **光ったマスをクリック** | 移動 / 攻撃（赤＝攻撃、青＝移動先） |
| **持ち駒チップをクリック → 盤面クリック** | 持ち駒を打つ |
| **能力カードをクリック** | ターン開始時に提示される3枚から1枚を獲得 |
| **⚡神の消滅ボタン** | 神がいるとき、敵コマ1体を消滅（3ターンに1回） |
| **💢罵詈雑言ボタン** | 盤上の「いやなやつ」を泣かせて追い払う |

### 勝利条件
- 相手の **王将を取る**、または
- 相手の **本拠地HP を 0** にする（コマが敵の最奥段に突入＝ブリーチでダメージ／一部の能力・特殊コマで直接ダメージ）

## ファイル構成

```
gsx/
├── index.html              # エントリ HTML（canvas + UIルート）
├── package.json
├── tsconfig.json
├── vite.config.ts
├── README.md
└── src/
    ├── main.ts                     # 全体の配線（描画 / UI / ゲームのイベント接続）
    ├── style.css                   # UIオーバーレイのスタイル
    │
    ├── core/                       # ── ルール・進行（描画やDOMに非依存）──
    │   ├── types.ts                # 共有型・列挙・レアリティ定義
    │   ├── constants.ts            # 盤サイズ・色・初期HPなどの調整値
    │   ├── Piece.ts                # コマの実行時インスタンス（HP/バフ/CD）
    │   ├── Board.ts                # 盤面状態 + 着手生成（ルールエンジン）
    │   ├── GameManager.ts          # ターン進行・能力適用・勝敗判定の統括
    │   ├── AIController.ts          # 簡易AI（優先順位ベースの評価）
    │   └── SpecialEffectManager.ts # タレット自動攻撃・オーラ・マス効果・増殖など
    │
    ├── data/                       # ── データ定義（追加しやすさの中心）──
    │   ├── pieceData.ts            # 全コマの定義（移動・HP・タグ・価値）
    │   └── abilityData.ts          # 能力カード定義（レアリティ別）＋抽選ロジック
    │
    ├── render/                     # ── 3D描画（Three.js）──
    │   ├── SceneManager.ts         # シーン/カメラ/ライト/操作/クリック→マス変換
    │   ├── BoardRenderer.ts        # 盤・コマ・ハイライト・特殊マスの構築と更新
    │   └── PieceMesh.ts            # コマ1個分の3Dメッシュ生成（漢字テクスチャ等）
    │
    └── ui/
        └── UIManager.ts            # DOMオーバーレイ（HUD/カード/パネル/ログ/勝敗）
```

### クラスと役割（要件のクラス構成に対応）
- **Piece** … コマ1個の状態（位置・HP・バフ・クールダウン）。静的定義は `pieceData.ts`。
- **Board** … 盤面グリッド・特殊マス・**着手生成**。描画/進行から独立した純粋ロジック。
- **GameManager** … 中枢。ターン制、カード提示・適用、移動解決、召喚、勝敗。
- **AIController** … 合法手の生成と評価で行動決定。
- **UIManager** … HUD・カード選択・各パネル・ログ・勝敗画面（DOM）。
- **SpecialEffectManager** … 「自動で起きる」処理（自動攻撃・オーラ・溶岩・増殖・威圧など）。
- 加えて描画用に **SceneManager / BoardRenderer / PieceMesh** を分離。

> **設計方針**: ルール処理（`core`）と描画処理（`render`）と UI（`ui`）を完全分離。
> `GameManager` は Three.js も DOM も知らず、**イベント**（`GameEvents`）だけを発火します。
> 描画・UI 側はそのイベントを購読して状態を反映します（`main.ts` で配線）。

## ゲームルール概要

- 9×9 の将棋盤。手前がプレイヤー（先手）、奥がAI（後手）。
- 基本の移動・成りは将棋に準拠（飛・角・金・銀・桂・香・歩・王、成駒含む）。
- 各プレイヤーに **本拠地HP（初期30）** があり、王将討ち取り or 本拠地HP0で決着。
- **コマにHP** の概念を導入。近接で取りに行く＝原則「取り」だが、HPの高い特殊コマ
  （ゴーレム等）は1撃で倒せないと**弾かれて**取れません（タンク表現）。
  タレット/弓などの**遠隔・継続ダメージ**は HP を削ります。
- **取った通常コマは持ち駒として再利用可（打てる）。特殊コマは持ち駒にならない**
  代わりに「不死鳥は復活」「爆弾兵は爆発」「いやなやつは呪い」など**死亡時の例外ルール**を持ちます。
- 毎ターン開始時、ローグライクの **能力カードが3枚** 提示され、1枚を獲得します。

## キャラクター（軍師・全6人）

タイトル画面 →「ゲームスタート」→ 軍師選択 で1人を選びます（AIはランダムで別の軍師）。
定義は `src/data/characterData.ts`。**パッシブは開始時に永続適用**、**奥義は奥義ボタンで発動**
（クールダウン制・ターンを消費しない）。

| 軍師 | パッシブ | 奥義（CD） |
|------|---------|-----------|
| **上杉謙信**（軍神）毘 | 毘沙門天の加護：自軍全コマ攻撃+1（永続・召喚にも適用） | 車懸かりの陣：追加行動+2＋自軍攻撃+2/2T（CD5） |
| **オタワさん**（古典教師モード）古 | 抜き打ち小テスト：毎ターン35%で敵1体が居眠り（行動不能） | 抜き打ち期末試験・古典：全敵1ターン行動不能＋敵本拠地3ダメージ（CD6） |
| **武田・風**（疾如風）風 | 疾きこと風の如し：毎ターン30%で追加行動+1 | 風の陣・極：追加行動+3＋自軍攻撃+1/2T（CD5） |
| **武田・林**（徐如林）林 | 徐かなること林の如し：自軍の防御+1（永続） | 林の陣・極：本拠地+10回復＋守護(防御+2)＋回復マス展開（CD5） |
| **武田・火**（侵掠如火）火 | 侵掠すること火の如し：自軍攻撃+1、敵を取るたび敵本拠地に飛び火1ダメージ | 火の陣・極：敵陣に溶岩3つ＋敵本拠地5ダメージ（CD5） |
| **武田・山**（不動如山）山 | 動かざること山の如し：自軍最大HP+1、本拠地最大HP+12 | 山の陣・極：本拠地＆自軍全回復＋鉄壁(防御+3)（CD6） |

> 新しい軍師は `characterData.ts` に1エントリ追加するだけ（パッシブ／奥義は
> `GameManager` の公開APIを呼ぶ関数として書きます）。タイトル・選択画面・AIは自動対応。

## 能力カード（レアリティ別・各5種以上）

`src/data/abilityData.ts` に定義。カテゴリ＝コマ強化／召喚／盤面ギミック／一時バフ／永続パッシブ／妨害／本拠地。

- **Common**: コマ強化, タレット増設, 鉄壁の守り, 回復の祝福, 徴兵, 応急手当
- **Rare**: 歩兵進化, 王の威圧, 神託, 呪いの盤面, 忍者召喚, 罠設置, ワープ門, 突撃ラッパ
- **Epic**: 二回行動, 駒の反乱, 重装召喚, 盤面拡張, 溶岩流, 不死鳥召喚, 神域展開
- **Legendary**: 神召喚, 大要塞, 全軍強化, 暗殺部隊, 神速, 聖団
- **Cursed**（強力だがリスク）: 禁断召喚, 血の契約, 疫病, ガラスの大砲, 悪魔の取引, 混沌の盤, 罵詈雑言＋

要件で指定されたカード（歩兵進化／王の威圧／タレット増設／神託／二回行動／呪いの盤面／
鉄壁の守り／駒の反乱／禁断召喚／盤面拡張）はすべて実装済みです。
**神託** は次に出るカードのレアリティ抽選を引き上げます。

## 盤面ギミック（特殊マス）

`SpecialEffectManager` と `GameManager.handleTileEnter` で解決。

| マス | 効果 |
|------|------|
| 回復マス | 止まったコマを回復（王将なら本拠地も回復） |
| 罠マス | ダメージ＋次ターン行動不能 |
| ワープマス | 対になるワープマスへ転送 |
| 召喚陣 | そのマス付近に特殊コマを召喚しやすくなる |
| 神域 | 神系コマを強化、通常コマを弱体化（ターン終了時） |
| 溶岩マス | ターン終了時、上のコマにダメージ |
| 呪いマス | 止まると次ターン行動不能 |

## AI の挙動（簡易）

`AIController` が全合法手を生成し、次の優先順位で評価して着手します。
1. 王将を取れるなら取る
2. 強い／特殊コマを取れるなら取る
3. 自分の王将を危険なマスに置かない
4. タレット・弓・神など危険なコマの射程から逃げる
5. それ以外は前進・ランダムな合法手

加えて、AI もターン開始時に能力カードを（自動で）選び、神がいれば消滅も使います。

## 拡張のしかた（追加実装しやすい設計）

データ駆動なので、多くの追加は**データを足すだけ**で済みます。

### 新しいコマを追加する
1. `core/types.ts` の `PieceType` に名前を追加。
2. `data/pieceData.ts` の `PIECE_DATA` に定義を1つ追加（移動 `pattern`、`maxHp`、`atk`、
   `tags`、`value` など）。移動は「歩兵視点（前方 = −row）」で書けば、AI側へは自動で反転されます。
3. 必要なら `SUMMONABLE_SPECIALS` / `PAWN_EVOLUTIONS` に登録。
4. 見た目のアクセント色は `render/PieceMesh.ts` の `SPECIAL_ACCENT` に1行追加するだけ。
   → これだけで移動・描画・召喚・AI評価に乗ります。
5. 「死亡時の特殊挙動」は `tags`（例 `death-explosion`）を付け、`GameManager.killPiece` /
   `SpecialEffectManager` に分岐を1つ足す形で拡張します。

### 新しい能力カードを追加する
`data/abilityData.ts` の `ABILITIES` 配列にオブジェクトを1つ追加するだけ。
`apply(game)` から `GameManager` の公開API（`spawnNearHome` / `buffOwnPieces` /
`addTiles` / `healHome` / `addPassive` / `grantExtraActions` …）を呼びます。
レアリティ抽選・UI 表示・所持一覧は自動で対応します。

### 新しい盤面マスを追加する
`core/types.ts` の `TileType` と `constants.ts` の色マップに追加し、
進入時効果は `GameManager.handleTileEnter`、ターン終了時効果は
`SpecialEffectManager.tileEffects` に分岐を足します。

## 既知の制限・今後の拡張余地（MVP のため簡略化）

- 王手放置の厳密な合法性チェックは省略（着手は擬似合法）。詰みの自動判定は未実装で、
  勝敗は「王将を取る／本拠地HP0」で判定します。
- 二歩などの打ち駒制限は最小限（最奥段の歩・香のみ禁止）。
- コマの移動はメッシュ再構築で表現（補間アニメーションは未実装）。
- AI は1手評価の簡易版（読みの深さなし）。`AIController` を差し替えれば強化可能。

## 動作確認について

`npm run build`（型チェック含む）と開発サーバー起動で動作を確認済みです。
ブラウザ上で、カード選択 → コマ移動 → AI応手 → 特殊コマ召喚 → 自動攻撃 →
勝敗画面まで、40ターン以上をエラーなく通すところまで確認しています。

デバッグ用に、開発時は `window.game` から `GameManager` にアクセスできます
（例: コンソールで `game.players.player.homeHp`）。
